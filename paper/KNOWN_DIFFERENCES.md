# Known differences between this source release and the manuscript

The manuscript keeps its own consistency audit (Supplementary Table S35, items R1–R35). This file is the
corresponding ledger for the repository: material places where the released source departs from the manuscript's
description, or where the manuscript reports something the source does not produce, with its status. Items are
numbered D1–D17 so that issues and pull requests can cite them. The resolution path we have chosen for each open
item—re-running with the released code, changing the code before the runs, or revising the manuscript—is in
[docs/STATUS.md](../docs/STATUS.md).

| Status | Meaning |
|---|---|
| **aligned configuration** | The stated configuration follows the registered value; the entry keeps the loss-specific distinction visible. |
| **declared choice** | The manuscript specifies counts, laws or interfaces but not every implementation detail; the choice made here is stated and tested, and a run records it in its artifacts. |
| **disclosed** | The source differs from the manuscript's setting in a way that affects the fresh-run quantities; the difference is stated so that comparisons are read correctly. |
| **implemented as reported** | The manuscript reports the quantity in a form the release now builds from every run. |
| **record contract** | The experiment runs outside the eight-stage lifecycle; its measurements enter as a record set under [`records/`](../records/README.md), with the raw logs every printed value is read from, and its table is printed from that set. |
| **outside the release** | An experiment, comparator or instrument of the manuscript is not part of this source package. |

## Model and sensing

| ID | Difference | Effect on fresh-run quantities | Status |
|---|---|---|---|
| D1 | **Parameter counts.** Supplementary Table S5 lists 3.1 M (arxiv), 3.52 M (proteins), 3.36 M (products), 2.52 M (Roman), 3.14 M (Pascal), 3.18 M (COCO) and 5.1 M (Peptides) parameters. The plants built by `cross_morse/core.py::build_plant` from `configs/*_full.json` have different counts (for example 1,138,216 for the arxiv plant with 128 inputs, width 512, four encoder layers and 40 classes). Every run writes its actual tensor inventory to `train/model_inventory.json`, which is the authoritative count for that run. | Scores of the plant (`qN`) and of every policy are those of the released architecture, not necessarily of the manuscript's plant; effects relative to `qC` are the comparison of interest. | disclosed |
| D2 | **Spectral windows.** The manuscript's band definitions were "selected inside training folds and then frozen". The release uses six equal-interval degree-8 Chebyshev windows with Jackson damping and retains bands `[0, 2, 5]` (`core.py::chebyshev_window_coefficients`, `MeasurementBank`). | Band powers and alignments are computed on fixed windows; the Lean/Full contrast is unchanged in form. | declared choice |
| D3 | **Encoder internals and native-site placement.** The shared-transport plant is an input linear + ReLU/dropout encoder, a shared linear/ReLU update, post-reference LayerNorm and a linear head; the heterophily plant adds a separate ego map; GPS native sites sit at the first transition of each block interval (`[1, 22, 43, 64, 85, 106]` of 128), linear-GINE native sites at `[0, 8, …, 56]` of 64. The manuscript gives counts (6 native + 122 inserted; 8 native + 56 inserted) and laws, not positions. | None on the identity test E1; positions are recorded in `instrumentation_metadata`. | declared choice |
| D4 | **Scalar edge weights.** Proteins: the transport weight is the mean of the eight edge-feature channels; Peptides: `1 + mean(bond categorical codes)`. The manuscript specifies nonnegative scalar edge weights but not the reduction. | Different reductions would change the kernels `P` and `S` on these two datasets. | declared choice |
| D5 | **Degree-stratified cores on proteins.** Degree-rank quantile strata, seeded shuffle and round-robin allocation into 32 balanced cores with a 2-hop buffer (`cross_morse/data.py`). The manuscript names the unit but not the algorithm. | Core membership, hence the descriptive intervals, depend on this construction. | declared choice |
| D6 | **Reduced sensor on proteins and PascalVOC-SP.** Supplementary Table S6c shows that full-state degree-8 sensing at every site would cost 2.95 (proteins) and 0.34 (Pascal) nominal steps against measured controller overheads of 0.20 and 0.31, so the executed sensor there was a sketch of width `k < d` or a longer period; the executed `(k, P_s, f_res)` are read from the execution record and are **not tabulated** in the manuscript. The shipped full profiles set `sensor.sketch_dim = 0` (full-state sensing) and `controller.observer_period = 2`. | Table S6c bounds `(k/d)/P_s ≤ 0.068` on proteins from sensing cost alone; at `P_s = 2` this allows `k/d ≤ 0.136`, before charging other work. Full-state sensing at period two still exceeds the proteins multiplier, while Pascal requires an actual complete ledger to assess the remaining budget. The bound √(2/k) concerns band-power estimation variance and does not guarantee task-accuracy or action-selection stability. The historical sensor settings and current measured work must be compared explicitly. The executed `(k, P_s, f_res)` enter as the `sensor_parameters` record set (E17), and the full profiles take those values once it is deposited. | disclosed |
| D7 | **Products execution.** The manuscript describes a partition-aware adapter with partition-local propagation and a buffered boundary. The release executes exact full-graph sparse propagation and chunks only dense calls (65,536 rows). | This is a declared full-graph execution choice. Equivalence to the paper's partition/buffer execution is not established without its boundary implementation. Dense-call chunking does not remove full-graph hidden-state storage. The reported 64.5 GiB GPU / 118 GiB CPU in Table S23 belongs to the paper's run; measure the current pilot before the full profile. | disclosed |

## Protocol and statistics

| ID | Difference | Effect on fresh-run quantities | Status |
|---|---|---|---|
| D8 | **Headroom oracle.** The manuscript's admission-stage oracle enumerates supported sequences of the registered beam per input (Supplementary Table S30, Proposition 4). The entry gate of the release (`select/entry_complete.json`) uses the best complete evaluated candidate of the registered family on D_explore at E = 1 (`statistics.global_candidate_oracle`); a per-core minimum is saved only as a diagnostic. | The gate `U(Δ_oracle) < −0.003` has the same form; its value is a finite-family quantity and is not the Table S30 dispersion. | declared choice |
| D9 | **Learned stop.** The manuscript's learned-stop route predicts the complete stopping depth from the initial input. The release implements an initial-measurement nearest-template predictor of the development-best depth. | A different open-loop member of the same family; it competes inside the nested comparator selection like every other open-loop route. | declared choice |
| D10 | **Separated data-use sequence on the multi-graph benchmarks.** The submitted protocol computed the PascalVOC-SP, COCO-SP and Peptides-func confirmation contrasts on the official validation split that also served admission (Table S39). The release confirms on D_confirm (10% of official training: 850 / 11,329 / 1,087 graphs) and admits on the untouched validation split (1,428 / 5,000 / 2,331 graphs), which is the pre-registered sequence of experiment E10. | Table S14b is analytical fixed-effect/SE-rescaling sensitivity, not an observed separated-data rerun or numerical replication target. Its model estimates Peptides radius-label retention at 0.36; the displayed failed-contrast outcome returns `qC` because one-step is outside Qs. Admission sizes remain unchanged, but a fresh formal claim also requires no adaptive use of those admission observations; a fresh split is needed if prior inspection was adaptive (Note S26). | disclosed (by design) |
| D11 | **Loss-specific registered margins.** Proteins and Peptides pilot/full profiles use `epsilon_r = epsilon_a = 0.0015` nats for mean multilabel BCE. The CE profiles use 0.003 (main text after Eq. 19; Table S13). | Different loss types use their own practical improvement thresholds; smoke fixtures have their declared testing settings. | aligned configuration |
| D12 | **Three readings of the selection rule.** Supplementary Table S12c audits main Eq. (19) on the representative rows under three equivalence readings: `ε_eq = 0.002` on `U_s` (the registered reading), `ε_eq = 0.002` on the point estimates `Δ̂_s`, and `ε_eq = 0.001` on `Δ̂_s`; on Roman-empire, PascalVOC-SP and COCO-SP the registered reading selects radius while MPC-RH was deployed, and the `0.001` point-estimate reading reproduces all seven decisions (manuscript item R14). The release deploys by the registered reading (`statistics.nested_selection`) and builds Table S12c from every run (`paper/build/selection.py`): the three readings on the representative rows, the route the run selected, and the registered rule applied to every configuration and checked against the run's sealed selection. | A run in which the readings disagree shows it in its own S12c row, in the form the manuscript reports. | implemented as reported |
| D13 | **Roman-empire within-run units.** The release additionally partitions each Roman split into 32 METIS cores for within-run descriptive intervals; the manuscript's unit is the official split, with a paired small-sample interval over the ten splits. | The ten-split campaign (`run_cross_morse_roman_empire.sh submit campaign full` + `scripts/summarize_roman_splits.py`) is the comparison path; within-run core intervals are diagnostics. | declared choice |
| D14 | **Entry-contract unit on the multi-graph benchmarks.** The manuscript's submitted gate statistics for Pascal, COCO and Peptides were computed on the complete validation graphs (a post-decision diagnostic); the release evaluates the gate on the training-only unit the contract prescribes. | Table S4 values for those three datasets are not the comparison target of `train/entry_initial.json`; a pass on one unit is not assumed to transfer. | disclosed (as in the manuscript) |

by hand finds them stated.
